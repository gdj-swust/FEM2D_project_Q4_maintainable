### [P2] [R3/R6] von_mises / principal_stresses 对 complex 输入静默错值或裸 TypeError

- **位置**: [fem2d/material.py:53-86](fem2d/material.py#L53-L86) (`von_mises`), [fem2d/stress.py:44-59](fem2d/stress.py#L44-L59) (`principal_stresses`)
- **现象**: 复数 dtype 应力数组是公开 API 的合法 numpy 输入, 但:
  - `von_mises(np.array([1+1j, 1.0, 0.0]))` → **静默返回 0.7071** (数学上复数按范数/虚部处理应得不同值; 实际 numpy 标量转换丢虚部, 仅发 ComplexWarning, 不抛错) — 违反全局约定 0 节 "不允许静默传播" 家族;
  - `von_mises(np.array([[1+1j,1,0],[1,1,1]]))` (批量) → 静默返回 **complex 数组** (类型污染下游);
  - `principal_stresses(np.array([1+1j,1.,0.]))` → 冒**无上下文的裸 TypeError** ("ufunc 'hypot' not supported") — 违反约定 0 节 "禁止裸 TypeError 冒出"。
- **证据/复现**:
  ```python
  import numpy as np
  from fem2d.material import von_mises
  from fem2d.stress import principal_stresses
  von_mises(np.array([1+1j, 1.0, 0.0]))          # -> 0.7071... (静默, ComplexWarning)
  principal_stresses(np.array([1+1j, 1.0, 0.0]))  # -> TypeError: ufunc 'hypot' not supported
  ```
  (本机实测复现; 批量 complex (2,3) 路径返回 complex 数组)
- **根因**: 入口只查 `np.isfinite(stress)` (complex 的有限性判定通过), 未查 dtype; 后续运算对 complex 产生数学上无定义的结果。
- **建议**: 入口校验 `np.iscomplexobj(stress)` → 带参数名的 ValueError (与 NaN/Inf 拒绝同族); 不必改公式路径。fuzz 值池需加入 complex 数组值 (当前值池只有 scalar complex, 无 complex 数组, 该盲区因此未被 fuzz 捕获)。
- **冻结区标注**: 非冻结区。冻结的是 "von_mises/principal_stresses 对 (n,3) **有限输入**输出逐位不变" — 增加输入校验不触碰输出路径, 属"只改入口校验"。

### [P2] [R2] `Merge "*.geo"` 绕过 SystemCall 拦截 (清洗器黑名单覆盖缺口, 已实证)

- **位置**: [scripts/gmsh_runner.py:133-170](scripts/gmsh_runner.py#L133-L170) (`_scan_include_tree` 只追 `Include` 指令), [scripts/gmsh_runner.py:249-290](scripts/gmsh_runner.py#L249-L290) (`sanitize_geo_source` 无 Merge 处理)
- **现象**: Gmsh 的 `Merge "file.geo"` 与 `Include` 同为"解析并执行被引用 .geo 脚本"的代码执行面, 但 SystemCall 黑名单的递归扫描只沿 `Include` 引用树展开。顶层 .geo 写 `Merge "evil.geo";` 时, evil.geo 内的 `SystemCall` 不被任何检测覆盖 — 拦截被完整绕过。
- **证据/复现** (本机实测, 临时目录内完成, 已清理):
  1. `sanitize_geo_source(open("main.geo").read(), geo_path="main.geo")` — main.geo 内容为 `Merge "evil.geo"; ...几何...` → **通过 (未拦截)**; 而直接 `sanitize_geo_source(evil.geo 内容, geo_path="evil.geo")` → 正常抛 GeoScriptRejected。即: 含 SystemCall 的文件作为 Merge 目标时不经过扫描。
  2. 用 bundled gmsh.exe 实际执行 main.geo, gmsh 日志显式输出 `Info : Calling 'cmd /c echo MERGED_EXECUTED > ...'` — **SystemCall 被 gmsh 真实调用执行** (标记文件写入因 cmd 路径引号问题未落地, 但命令已被调用, 属执行的直接证据)。
- **根因**: 黑名单是"正则 + 词法扫描"模型, 覆盖范围按指令逐条枚举; Gmsh 脚本语言的执行面 (Include / Merge / 宏 / 菜单) 未被系统性枚举, Merge 是其中与 Include 同族却漏网的向量 (R7 增量审查确认 S8 轮只承诺 Include, 但缺口依然成立)。
- **影响评估**: .geo 属"可信、可执行式输入" (文档化威胁模型), SystemCall 拦截是运行他人共享 .geo 时的安全网 — 该网可被一行 `Merge` 击穿。实际危害取决于用户是否运行不可信 .geo; 属防御纵深缺口, 非 RCE 面扩大 (攻击者本可直接写 SystemCall 在自己文件里, 但**共享文件的扫描承诺因此失效**)。
- **建议**: `_iter_geo_includes` / `_scan_include_tree` 同时识别 `Merge "path"` 指令 (语法与 Include 同构: `\bMerge\s*"[^"]*"`), 纳入同一递归扫描与循环检测; 或在 sanitize 中对 `Merge "*.geo"` 一并替换为注释。两路径 (API + 子进程) 共用清洗器, 改一处即双路生效。
- **冻结区标注**: 非冻结区 (清洗器正则增强, 不触碰任何数值/识别算法)。

### [P3] [R2] sanitize_geo_source 的 `Mesh.Format` / `Mesh.MshFileVersion` 正则行首锚点可被同行前导语句绕过

- **位置**: [scripts/gmsh_runner.py:278-289](scripts/gmsh_runner.py#L278-L289)
- **现象**: `Mesh.Format = 39;` / `Mesh.MshFileVersion = 2;` 的剥离正则带 `^\s*` 行首锚点 — 前面有任意语句的同行写法 (`x = 1; Mesh.Format = 39;`) 完全绕过。而 `Save`/`Mesh 2` 正则 (`\b` 匹配, 无锚点) 不受影响 — 同类指令处理不一致。
- **证据/复现**: 正则单元测试 (本机实测): 7 种写法中仅 "行首" 与 "行首带缩进" 被剥离; `'x = 1; Mesh.Format = 39;'` 与 `'SetFactory("OpenCASCADE"); Mesh.MshFileVersion = 2;'` 均原样保留。
- **影响**: `Mesh.MshFileVersion = 2` 保留 → gmsh 输出 MSH 2.2 → 生成物标记 (仅 4.x) 注入失败 → 覆盖保护失效 + 物理组恢复 WARN (静默降级); `Mesh.Format = 39` 保留 → 临时 .msh 路径被写入 Abaqus 格式 → 下游 import 失败 (响亮失败, 非静默错值)。
- **建议**: 去掉 `^\s*` 锚点, 与 Save 同款 `\bMesh\s*\.\s*Format\s*=` 匹配 (注释剥离后无字符串干扰)。
- **冻结区标注**: 非冻结区 (同 P2-2, 清洗器增强)。

### [P3] [R4] `fix_node` 每次调用 O(k log k) 全量重建 fixed_dofs — CLI 整边固支 O(n² log n)

- **位置**: [fem2d/mesh.py:590-628](fem2d/mesh.py#L590-L628) + [fem2d/bc_apply.py:163-164](fem2d/bc_apply.py#L163-L164)
- **现象**: `fix_node` 每次执行 `set(self.fixed_dofs.tolist())` + `np.array(sorted(existing))` — 对**整个已约束 DOF 集**做一次 O(k log k) 排序重建。bc_apply 对整条边的每个节点循环调用 (`for n in segs[idx]['nodes']: mesh.fix_node(...)`)。
- **证据**: 代码路径可直接推导: 约束一条 n 节点边 = n 次调用 × 递增的 O(k log k) ≈ O(n² log n); 10 万节点细密网格整边固支 ≈ 10¹⁰ 次操作。这是本次审查在主路径 (CLI 求解必经) 发现的**唯一结构性超线性**。
- **建议**: bc_apply 层批量收集全部 DOF 后一次性 `np.unique` 写回 (fix_node 单点语义不变); 或 Mesh 内部维护 Python set, 到 `_partition_dofs` 才落盘数组。改后需漂移门复验 (求解结果不受影响, 仅路径重构)。
- **冻结区标注**: 非冻结区。

### [P2] [R5/F 边界管线] `_merge_adjacent_lines` 把非共线直线合并成弯曲"直边"段

- **现象**: 合并判据是 `axis` 三档粗分类 (x: 80°-100° / y: <10°|>170° / tilted: 其余) 相等 + `|pos_i - pos_j| < scale×0.02`; 而 tilted 线的 `pos` 就是**起点 x 坐标** (line.py:64)。两条夹角 30° 的非共线斜线, 只要共享端点且起点 x 落在模型尺度 2% 内, 即被合并成一条 n=3 的"直边"段 — 中点到弦偏离达弦长 13%。

### [P3] [R6] float32/float16 批量应力数组被静默按低精度计算
