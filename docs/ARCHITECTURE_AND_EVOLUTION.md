# FEM2D 架构评估与演进路线图

> 版本: 9.28.0（2026-08-06）。读者: 保研大工计算力学方向 + 项目长期维护者。
> 依据: `docs/CODE_MAP.md`（代码地图）、`COMMANDER_HANDOFF_20260805c.md`
> （交接/教训）、`CHANGELOG.md`、`docs/ci.md`、`docs/api_contract.md`、
> `docs/performance.md`。本文件只做评估与建议，不改变任何行为。
> 现状数字: 源码约 1.8 万行（fem2d/ 实测 18379 行）/ 测试约 2.7 万行（27202 行）、
> 1552+ 测试函数（pytest 收集 1628）、覆盖率 98.3%（2026-08-06 本机实测，
> 无捆绑 gmsh.exe）、CI 七 job、审查评分 8.4/10。

## 一、架构现状评估

### 1.1 总体: 五阶段数据流（runner 主线）

单入口 `run.py` → 纯转发 `runner.main`，一次分析固定走五个阶段：

```
阶段1 _resolve_input     .spec / .geo / .txt / .msh 四种输入统一分派
阶段2 _build_model       网格导入校验 + @FEM 配置合并 + 边界模型
阶段3 _apply_conditions  fix / traction / force / body 四类条件施加
阶段4 _analyze_and_report 求解 + 误差估计 + 中文报告
阶段5 _plot              云图 / isoband / 交互
```

职责由 35+ 顶层模块 + `element/`、`boundary/` 两个子包分摊，单一主线、无旁路入口，
这是本项目可维护性的第一支柱。

### 1.2 关键机制

| 机制 | 内容 |
|---|---|
| 内核注册协议 | `ElementKernel` ABC + `register_element`/`get_element_kernel` 注册表；CST（显式形状函数）/ Q4（2×2 积分）/ Q4I（QM6 非协调 + 静力凝聚）/ Q4R（单点积分 + 沙漏稳定）；Mesh 构造时浅拷贝 kernel，防可变类属性跨 Mesh 污染 |
| 边界识别管线 | `build_boundary_segments` 优先级 RegionRegistry → edge_labels → 纯拓扑 detect；邻接图 → 闭环分解 → 嵌套定向 → 曲率分割 → 自交检测；detectors 插件体系首个非 None 胜出，GeneralCurveDetector 兜底恒返回 |
| 装配 4 路径 | sparse / sparse_vectorized / lil_reference（教学参考）/ expand；向量化路径为生产默认 |
| 求解三分支 | 纯 Dirichlet（空矩阵特判）/ 消去（Bathe §4.2.2，默认）/ 罚；奇异守卫把秩警告转异常、非秩警告转发；刚体模态逐连通分量 rank 检查；全局平衡用相对尺度判据 |
| 错误体系 | `checks.py` 共享校验 helper；用户误用 → 带上下文的 ValueError/TypeError/CliError；NaN/Inf 一律拒绝，禁静默传播 |

### 1.3 强项（诚实评估）

1. **冻结区边界清晰**：element/ 内核公式、solver 数值逻辑、error_est 公式、
   边界识别算法被明确冻结（"只改入口校验"/"只加插件标签"），配合金标准快照
   （boundary_golden + solve_refactor_lock 逐位锁）与漂移门（基线 7ee65fc，
   相对差必须 0.0），大优化轮（A 清理/B 结构/D 易用性/E 解析解）多轮并行
   合并后数值行为零漂移——这是教学求解器最怕踩的坑（错误结果无报错），
   已被机制锁死。
2. **契约文化落地**：`docs/api_contract.md` 契约表 + 探针 151 项断言 +
   判别性测试映射（每个 ✅ 有"放回旧实现必须失败"的测试在场），K1-K13
   缺口全部闭环。API 误用路径（形状/类型/NaN/越界/布尔掩码）有统一错误
   语言。
3. **测试体系纵深**：金标准 / 漂移门 / 探针 / fuzz（固定种子 500）/ 分支锁 /
   解析解验证（E 轮悬臂梁、Kirsch Kt→3、Z2 效应指数 θ∈[0.8,1.2]）六层，
   1552+ 函数，覆盖率 98.3%。
4. **微尺度鲁棒性**：禁绝对阈值（相对尺度 + `np.finfo(float).tiny`），
   1e-150 几何 / 1e12 坐标 / 1e-310 载荷全链路必须保持有限，perf 脚本每次
   运行末尾做微尺度冒烟——历史"乘大数罚因子刚度平方、绝对阈值误杀"类
   缺陷已被制度化拦截。
5. **错误不会静默**：NaN/Inf 快速失败、奇异矩阵抛异常（不返回 NaN/零解）、
   刚体模态不足禁止求解——静默错误比崩溃危险的教训已内建为约定。

### 1.4 弱项（诚实评估）

1. **gmsh 双路径维护成本**：API 路径（`_gmsh_session`，generate_from_geo /
   import_msh）与子进程路径（捆绑 gmsh.exe `-nt N -2`）并存，共用
   `_extract_mesh` 但各自持有调用栈与配置语义；安全净化（SystemCall
   词法剥离 + Include 递归扫描）需要两处同步维护。`.geo` 被视为
   "可信可执行输入"，其解析（@FEM 注释）与安全层是本项目最需要
   小心改动的区域之一。
2. **语义区域映射过渡期**：PhysicalEdgeMapper 已弃用（警告 + 工厂静默
   回退），RegionBoundaryMapper 是新主线，但弃用对象仍留在代码中——
   存在"两条映射路径行为假设不一致"的隐患，需在合理时机删除。
3. **冻结区是双刃剑**：冻结带来数值安全，也让重构成本升高——任何
   跨冻结区改动都要金标准逐位一致 + 回归 0.0 双验证，长函数拆分
   （B 轮）只能在冻结区外做。这是有意取舍，但要意识到它限制了
   未来内部结构优化的余地。
4. **文档是静态快照**：CODE_MAP 标注基于 main @ 9.28.0（2026-08-06 更新），
   版本合并后行号/结构可能漂移；文档不自动随代码更新，
   需人工记账（CHANGELOG 已承担部分，但代码地图/性能基线仍靠纪律）。
5. **并行包的历史包袱**：多个旧 worktree/分支待清理（pkg1-6/cleanA/
   structure/coverage/usability/analytic），系统 Python 残留 9.14.1
   editable 安装指向旧目录——不影响功能，但增加新人进入时的认知噪音。
6. **性能实测覆盖有限**：性能基线只覆盖规则网格档位，真实工程网格
   （质量差、条件数大）的时间行为未做系统 profile（详见第三节，
   不做过测断言）。

## 二、可维护性

### 2.1 当前维护约定（已生效）

| 机制 | 内容 | 触发时机 |
|---|---|---|
| 金标准 | boundary_golden 段 schema（不得新增键）+ solve_refactor_lock 逐位锁 | 每次提交 |
| 漂移门 | `scripts/regression_compare.py`，基线 7ee65fc，6 项指标相对差 < 1e-9 | CI test-full + 本地 |
| 探针 | `scripts/audit_contract_probe.py` 100 项契约断言 0 FAIL | 提交前 |
| fuzz | `scripts/fuzz_api.py 500` 固定种子 + combo_fuzz | 提交前 |
| 判别性测试 | 修复必须附"放回旧实现必失败"的测试 | 每修复 |
| 分支锁 | test_{solver,runner,stress,error_est}_branches.py | 全量 pytest |
| 覆盖率门 | CI test-full fail_under=90 | CI |

工程约定（第零条到第七条）: 每提交必全量 pytest 0 失败；修复流程
= 最小复现 → 修复 → 判别性测试 → 全量；禁绝对阈值；DOF 约定
x→2n、y→2n+1；gmsh 必须 `-nt N` + `-2`；无 gmsh 环境测试 skip
不失败；注释不写历史叙事（只留"为什么"）。

### 2.2 建议

- **可以更省的地方**:
  - 漂移门基线随版本演进刷新后，把"重跑漂移门 + 探针 + fuzz"固化为一
    条提交前脚本链（现在是人工三步），降低漏跑概率、省认知开销。
  - 覆盖率数字（98.3%）建议在每次大合并后从 CI 产物回填一次到
    CODE_MAP/本文件，避免"文档数字 vs 实际"漂移（当前 98.3% @
    9.28.0 本机实测，2026-08-06）。
  - worktree/分支/过期 editable 安装清理是一次性低成本维护，建议
    在 B/D/E 验收合并后集中做一次。
- **雷区（触碰必按特殊程序）**:
  - element/ 内核公式、solver 数值逻辑、error_est 公式——只改入口校验，
    先金标准 → 逐位一致 → 回归 0.0。
  - 边界识别管线——只加插件/标签/输入，识别算法冻结；段 schema
    金标准锁定，不得新增键。
  - `von_mises`/`principal_stresses` 对 (n,3) 输出逐位不变；
    `apply_penalty` 对有限输入数值逐位不变。
  - `cg_rtol` 必须保持 1e-10（实测 1e-8 污染支反力，被平衡检查误杀）。
  - 不重复修复已有注释标记"审计"的已修项；不重写历史叙事注释。
  - 新文件/模块避免与 loads.py 式"纯 facade"重复实现（历史教训:
    两处实现行为静默分歧）。

## 三、性能

> ⚠️ 本节全部判断基于 CODE_MAP 结构与 docs/performance.md 既有实测，
> **未在本轮做新的实测，标注"待 profile 验证"**；不承诺未验证的结论。

### 3.1 热点判断（待 profile 验证）

| 阶段 | 现状判断（基于结构与已知基线） | 待验证点 |
|---|---|---|
| 连接/几何（阶段2） | 向量化，近线性（规则网格 300k CST ≈ 440 ms） | 真实工程网格的边界识别耗时（拓扑闭环/曲率分割最重） |
| 装配（阶段3/4） | 4 路径并存，生产走向量化；规则网格近线性（300k CST K 组装 ≈ 490 ms） | 非规则/混合网格下 vectorized 与 expand 的差异 |
| 求解 | 消去法超线性（fill-in）；CG 迭代数是本质（条件数 ∝ 网格质量），非 Python 层可微调；ILU 预条件不可行（fill-in 内存 + 非 SPD） | 大网格 CG 的真实迭代数与网格质量关系 |
| 后处理 | L2 恢复已向量化（3×）；SPR 占 estimate ~78% 且位于冻结区外文件 | SPR 补丁构建（_node_patch_csr）在 100k+ 单元的耗时占比 |
| 启动 | matplotlib import 约 1-2 s，`--no-plot` 路径已避免 | — |

结论倾向: 唯一"算法级热点"是求解器的 CG 迭代数（谱性质决定），
不是微优化能改变的；其余阶段已在向量化路径上近线性。
**任何性能优化主张都应先 profile（`scripts/perf_benchmark.py`）再动手，
尤其禁止凭直觉改冻结区**。

### 3.2 微尺度硬指标

1e-150 微尺度模型是全程硬指标: 连接/组装/求解/L2/误差估计全链路必须
全有限（绝对阈值在此暴露）。`perf_benchmark.py` 每次运行末尾做
1e-150 冒烟，改动后重跑即可回归。

### 3.3 性能回归保护

`scripts/perf_benchmark.py`（1k/10k/100k/300k 档 + `--mem` + JSON 环境
指纹）是既有基线，跨版本对比直接重跑。建议: 每次发布前跑一次
100k 档，任何阶段时间退化 > 30% 即告警（待 profile 确认后定阈值）。

## 四、演进路线

> 优先级说明: 与用户"不开发新功能，优化完善"的方向对齐；
> **模态/热应力等研究扩展为"待办备选"，用户未拍板前不主动做**。

### P0 收尾清账（建议近期，零冻结区风险）

1. **C 覆盖轮收尾**: 验收合并 C-α 补测 → 合并后重跑覆盖率确认 98.3%
   真值 → 90% 硬门（CI test-full 背书）。影响面: 纯测试，无冻结区风险。
2. **B/D/E 遗留收尾**: 升版/CHANGELOG 记账已随 9.26.0 完成；
   补 `docs/api_contract.md` 单向量 `(3,)` 条目（6c 契约扩展伴随更新）。
3. **环境清理**: 旧 worktree/分支删除 + 系统 Python 9.14.1 残留卸载提示。

### P1 教学价值优先（不新增功能，优化完善）

4. **文档同步**: CODE_MAP/本文件/性能基线在每次大合并后刷新行号与数字。
5. **示例与教学路径打磨**: 现有模型（椭圆孔内压 demo 等）的输出
   讲解质量、错误信息引导（D2 已铺路）继续完善。

### P2 研究扩展（⏳ 待办备选 — 用户未拍板前不主动做）

| 备选 | 影响面 | 冻结区风险 |
|---|---|---|
| 模态分析（特征值） | 需质量矩阵 + 特征求解分支 | **高** — 触碰 element/ 内核（质量阵）与 solver 数值逻辑，须先金标准逐位验证 + 特殊程序 |
| 热应力（温度载荷） | 需热应变本构 + 热载荷项 | **高** — 触碰 element/ 内核与载荷装配 |
| 大变形/非线性 | 需增量求解器 | **极高** — 触碰 solver 核心，现有冻结机制需先扩展 |
| 3D 扩展 | 全新单元族 | **极高** — 架构边界（2D 假设遍布）先重构 |

上述备选写在此处仅为记录候选，不预埋代码、不做技术债；
用户拍板后单独立项、按冻结区特殊程序走。

## 五、对用户的建议（可执行）

1. **先收尾再评估**：优先验收合并 B/D/E 与 C 覆盖轮（98.3% 覆盖率确认、
   90% 硬门），把并行分支收敛到单主线后再谈其他——当前多 worktree
   并存是最大的隐性维护成本。合并后 push main 触发 CI 七 job，
   红一个都不算完成。
2. **用 profile 代替直觉优化**：性能问题先跑 `scripts/perf_benchmark.py`
   拿基线，热点（大概率在 CG 迭代数与 SPR 补丁）确认后再动；
   冻结区外的优化（后处理/输入解析）收益明确，冻结区内一律不动。
3. **维护纪律保持**：继续遵守"每提交全量 pytest 0 失败 + 判别性测试
   + 金标准逐位一致"；把探针/漂移门/fuzz 固化成一条提交前脚本链，
   把纪律变成命令而不是记忆。
4. **文档随代码走**：每次大合并把 CHANGELOG / CODE_MAP / 覆盖率数字
   一次刷新到位（现在是靠交接文档人工记账，容易漂移）。
5. **待办备选列而不做**：模态/热应力等研究扩展写在路线图里、
   不进代码；等用户拍板方向后单独立项，按冻结区特殊程序执行——
   与"不开发新功能，优化完善"的既定方向保持一致。
